Motivation

Standard VQA is a Closed-Book Exam

Closed-Book (Standard VQA)

Model sees one image + question.
Must answer from internal weights alone.
No access to prior examples or similar cases.

Hard questions about rare objects, unusual angles, or uncommon answers may never appear in training distribution. The model has no fallback.

Open-Book (This Project)

Model retrieves similar past VQA examples from a visual memory before answering.
Uses retrieved Q&A pairs as contextual hints.

Key question: can a frozen VQA model answer better if it can look up visually similar past examples?

Problem Statement

Visual Question Answering

Input
  • Image — a natural photograph
  • Question — a short natural-language question about it
Output
  • A short natural-language answer (1–3 words)
  • Evaluated with VQA soft accuracy: min(1, matches/3)
Challenge
  • Frozen BLIP-2 must answer from weights alone
  • Fails on open-ended visual details (what color, how many, what type)
  • Rare objects and uncommon scenes are underrepresented
  • Retraining a 3B-parameter model is expensive

Goal: improve a frozen model at inference time using retrieval — no fine-tuning required for the main result.

Key Insight

Why Does Visual Retrieval Win?

Image retrieval (α=1.0)

  • Similar images share objects, scenes, colors, actions
  • Visual neighbors often have similar answer distributions
  • CLIP image embeddings are rich and visually discriminative

Example: "Is the grass green?" — an image of a park retrieves other park images. Retrieved answers include "yes" and "green" — directly helpful.

Text retrieval (α=0.0) — hurts

  • Short VQA questions are often generic: "What color?", "How many?"
  • Same question form → different images → different answers
  • CLIP text embeddings optimized for captions, not interrogatives

Example: "What color is the car?" text-retrieval finds other color questions — but about completely different cars. The retrieved answers are noise.

Metric Honesty

Should Semantically-Correct Count? — Re-scoring Under Three Regimes

The question
BLIP-2 baseline on the skateboarder: "Watching the skateboarder" · GT: "watching". Strict VQA marks this WRONG because it requires exact-string match. But the answer literally contains the canonical word. Shouldn't that count?
Three accuracy regimes, same 100 predictions, no new inference:
STRICT — exact match (the existing 60.33% headline).
LENIENT — GT appears as a whole word in the answer. Rewards verbose-but-correct; rejects degenerate blueblue.
SUBSTR — GT appears anywhere. Most permissive.
How the metric works · only the match condition changes
VQAv2 gives 10 human annotators per question — they don't always agree, so the metric is consensus-based. A prediction is fully correct if it matches at least 3 of the 10 annotators (cap at 1.0). Matching fewer gives partial credit. The cap accounts for honest annotator disagreement on subjective cases like "red" vs "crimson".
# p = predicted answer · G = {g₁,…,g₁₀} = the 10 annotators
Acc(p, G) = min( #{ g ∈ G : match(p, g) } / 3 , 1.0 )
OverallAcc = mean over all questions in the eval
So matching 0 annotators → 0.0, 1 → 0.33, 2 → 0.67, 3 or more → 1.0. Only the match function differs across the three regimes.
norm(s) = lowercase · strip punct · drop a/an/the · collapse ws
strict : norm(p) == norm(g)  (exact equality)
lenient: norm(g) is a whole-word substring of norm(p)
substr : norm(g) appears anywhere in norm(p) (no token boundary)
The whole-word requirement on lenient prevents "hat" from spuriously matching inside "chat". SUBSTR is the looser variant without that guardrail — included as the upper bound only.
Worked example · the skateboarder case
Prediction p = "Watching the skateboarder"  →  norm(p) = "watching the skateboarder"
Annotator answers G include "watching" · "watching skater" · "looking" · …
Take g = "watching":
  strict : "watching the skateboarder" == "watching"  →  FALSE
  lenient: "watching" appears as a whole word in the prediction  →  TRUE
That single annotator match raises the per-question score from 0.0 (under strict) to at least 0.33 (under lenient). When this pattern repeats across many questions, the baseline jumps 42.33% → ~65%.
Implication chain. strict ⇒ lenient ⇒ substr — the rules get weaker, so per-question accuracy can only stay the same or go up. Therefore overall accuracy under each regime satisfies strict ≤ lenient ≤ substr.

What this means for our +18. The headline +17.00 strict → +1.00 lenient collapse isn't a contradiction — it's an interval bounding where the true semantic improvement lives. The lower end (+1) is the conservative estimate; the upper end (+18) is the form-effect-inflated number. Honest reporting requires showing both.
The three regimes · what each one actually does
1 · STRICT — exact-string equality (the published VQAv2 protocol)
Rule: norm(p) == norm(g). The normalized prediction must equal the normalized annotator answer character-for-character.
Matches: p="watching" against g="watching" → ✓.
Misses: p="watching the skateboarder" against g="watching" → ✗ (different strings, even though semantically right). Also misses synonyms ("gelato" vs "ice cream") and any verbose paraphrase.
Why we report it: it's the published protocol. Every VQAv2 number in the literature uses this. Comparable across papers.
2 · LENIENT — whole-word substring (rewards verbose-but-correct)
Rule: the normalized annotator answer appears as a whole word inside the normalized prediction. Token boundaries respected (regex \b…\b).
Matches: p="watching the skateboarder" against g="watching" → ✓ (the word "watching" appears with both boundaries clean). p="riding a bike" against g="bike" → ✓.
Still misses: word-order paraphrases ("the skateboarder is watching" only matches if "watching" appears as a token — fine here, but reordered noun phrases like "a yellow ripe banana" vs "ripe yellow banana" can fail). Also misses true synonyms (gelato ↔ ice cream).
Guardrail: the whole-word boundary blocks the "hat"-inside-"chat" false-positive. Without it, p="chat" would falsely match g="hat".
Why we report it: it's the cheapest deterministic relaxation that catches the verbose-but-correct case — which the slide-8 headline turns out to depend on heavily.
3 · SUBSTR — anywhere-in-string (upper bound · diagnostic only)
Rule: norm(g) in norm(p) — the annotator answer appears anywhere in the prediction, with or without word boundaries.
Matches: everything LENIENT matches, plus boundary-bleed cases like p="redhead" against g="red".
False positives: p="chat" against g="hat" → ✓ (incorrectly!). p="grandmother" against g="mother" → ✓. SUBSTR over-credits any prediction whose characters happen to contain the GT.
Why we report it: as the upper bound of the interval only. We don't claim it's the right metric — we use it to sandwich the true semantic accuracy from above. If even SUBSTR's loose rule still gives baseline ≈ 66% and RAG ≈ 68%, then the gap is at most ~2 points under any reasonable semantic check.
How the three numbers tell one story: strict +17 · lenient +1 · substr +2. STRICT inflates the gain by penalising baseline's verbosity. LENIENT and SUBSTR agree closely on the *real* gain (~+1 to +2) — meaning the +16 collapse from STRICT is robust, not a fluke of one relaxation.
Honest re-framing
The headline +17 RAG gain was ~16 pts of format compression + 1 pt of net-new information. Under semantic correctness, the model already knew most of these answers — RAG just nudged it to the canonical short form.

This is more interesting than the original story: VQA scoring rewards models that produce short answers; RAG is a frozen-model way to make BLIP-2 short. Real improvement on hard cases is +1 (still meaningful), but the form effect is the larger lever.

KB Scaling Win

KB scale + image-id-disjoint sampling gives 17 absolute points over a frozen baseline — without retraining, without prompt engineering. More retrieval coverage is the highest-leverage change in this system.
Why KB scaling matters here
  • → Original 5k KB: ~850 unique images (~5.9 Q per image)
  • → Image-id-disjoint sampling — no leakage between KB and eval
  • → Decomposing failures: 87% are retrieval-bound (answer not in top-3)
  • → Bigger / more-diverse KB targets the dominant bottleneck directly
Out-of-distribution mitigation: τ-gate
For out-of-distribution images (e.g. live-uploaded photos that don't match KB scenes), retrieval scores drop below 0.7. The τ-gate skips retrieval and falls back to baseline when top score < τ — visible in the live demo, prevents the harmful-RAG flip on novel inputs.
Future work direction this points to
→ Scale KB to 50k+ unique images (we're at 20k; VQAv2 has more)
→ Train a retriever specifically for VQA-relevant features (not generic CLIP)
→ Both target the 87% retrieval-bound failure category

Most striking: on the clean 20k KB, k=3, k=5, k=10 all give exactly 59.33%. The earlier 91% at k=10 was driven by image-id leakage in the 5k validation-built KB — not a real ceiling. k=3 is saturated at this generator size.
What this rules out
→ Adding more retrieved hints (k>3) doesn't help.
→ Mixing image+question retrieval (α<1.0) hurts.
→ Cross-encoder reranking and self-consistency don't help at this scale.
→ Evidence-aware selector overrides correct RAG with worse retrieved answers more than it helps — keep as a demo toggle, not a benchmark default.
→ Only routing-by-question-type helps. The bottleneck is the generator's use of evidence on yes/no, not retrieval coverage.

Conclusion

Open-Book VQA — Summary

Contributions
  • Built open-book VQA: BLIP-2 + CLIP + FAISS pipeline
  • Improved frozen BLIP-2 from 42.33% → 59.33% with retrieval (+17 pts), → 60.33% with type-conditional gating (+18 pts)
  • Visual similarity is a stronger retrieval signal than question-text similarity
  • RAG outperforms answer overlap at low k — model reasons over context
  • Main gain is on open-ended questions (+14 pts)
Limitations & Future Work
  • RAG slightly hurts yes/no questions (context adds noise)
  • Generator does not always use retrieved evidence reliably
  • 100-sample eval; full benchmark evaluation is future work
  • Image-disjoint KB construction should be enforced more strictly
  • Fine-tuning needs larger rank / more data to improve results
