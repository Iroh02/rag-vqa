01  /   INTRODUCTION
CrewAI

What is CrewAI?

An open-source Python framework for building collaborative AI agents that work together as a "crew" — each with a defined role, goal, and personality — to complete complex tasks.

👥

Role-Based

Agents are defined by who they are: a Researcher, a Writer, an Analyst — each with their own expertise and tools.

🤝

Collaborative

Agents communicate, delegate work to one another, and reach consensus — like a real team.

⚡

High-Level

You describe the team and the goal. The framework handles coordination and handoffs automatically.

02  /   THE PROBLEM
Why Multiple Agents?

Why not just one big LLM call?

A single agent doing everything has the same problem as a one-person company — too many roles, no specialization, weak quality.

❌ Single Agent

  • One generic prompt trying to do research, writing, and editing
  • Long context window mixing unrelated info
  • No specialization — jack of all trades
  • Hard to swap a single capability
  • Quality degrades on multi-step problems

✅ CrewAI Crew

  • Each agent focused on one role with the right tools
  • Clean context per task, less noise
  • Specialists deliver higher-quality output
  • Swap one agent without touching others
  • Mirrors how human teams actually work

04  /   AGENT
Deep Dive

The Agent — Anatomy

An Agent is an AI worker. Five fields define everything about how it thinks and behaves.

role REQUIRED
The job title. Frames the agent's perspective. "Senior Research Analyst" reasons differently than "Junior Intern".
goal REQUIRED
The agent's specific objective — what success looks like for THIS agent. Use {variables} to inject runtime context.
backstory REQUIRED
The persona — past experience, expertise, voice. Sounds silly, dramatically improves output quality by anchoring the LLM in a character.
tools OPTIONAL
A list of tools the agent can call. Without tools, the agent can only think. With tools, it can search, read, write, compute.
llm / allow_delegation / max_iter CONFIG
Which model powers it (gpt-4o, claude-sonnet-4-6, etc.), whether it can ask other agents for help, and how many tool-call loops are allowed.
05  /   AGENT TYPES
Common Patterns

Five Common Agent Types

Patterns that appear in nearly every multi-agent system.

🔬

Specialist Agent

Does one thing well. The Researcher, the Writer, the SQL Analyst. Most agents you build will be specialists.

Most common
👔

Manager Agent

Used in hierarchical processes. Receives the goal, breaks it into sub-tasks, delegates, evaluates outputs.

Hierarchical mode
✅

Validator / Critic

Reviews another agent's output for accuracy, tone, or compliance. Often added as the final step in a pipeline.

Quality control
🧩

Synthesizer Agent

Aggregates outputs from multiple parallel agents into a single deliverable. Common in research pipelines.

Aggregation
🛠️

Generalist Agent

Handles miscellaneous work that does not fit a specialist. Use sparingly — when you reach for a generalist, consider splitting the role into two specialists instead.

Use rarely

07  /   TASK
Deep Dive

The Task — Anatomy

A Task is a unit of work assigned to one agent. The framework executes tasks in order, passing outputs between them.

description REQUIRED
What the agent must do. Be specific. Bad: "Research X". Good: "Research X and find 5 verified sources with publication dates."
expected_output REQUIRED
The format and shape of the result. CrewAI uses this to validate completion. Vague expected outputs cause infinite loops.
agent REQUIRED
Which agent owns this task. One task = one owner. (In hierarchical mode, the manager assigns dynamically.)
context OPTIONAL
A list of other tasks whose outputs become input to this task. This is how data flows through the crew.
output_file / output_pydantic / output_json OPTIONAL
Persist the output to disk, validate it against a Pydantic model, or parse as JSON for structured downstream use.

Human-in-the-loop Task — "Pauses to ask a human for input or approval before continuing. Critical for high-stakes workflows."

Tip: "Most prototypes start sequential. Async and conditional come into play once you optimize." '>
08  /   TASK TYPES
Workflow Patterns

Five Types of Tasks

CrewAI supports several task patterns to fit how real workflows actually run.

Sequential Task DEFAULT
Runs after the previous task. Output of task N becomes context for task N+1. Easiest to reason about.
Contextual Task
Receives outputs from multiple specific earlier tasks via the context=[task_a, task_b] parameter. Enables non-linear flows.
Async Task
Set async_execution=True. Runs in parallel with other async tasks. Massive speedup for independent work.
Conditional Task
Wrapped in ConditionalTask(condition=fn, ...). Skipped if the condition function returns False. Used for branching logic.
Human-in-the-Loop Task
Set human_input=True. Pauses execution to ask a human for review or approval before continuing.

09  /   CREW
Assembly

The Crew — Putting It Together

A Crew is the team itself. It binds agents, tasks, and a process into one runnable unit.

from crewai import Crew, Process

crew = Crew(
    agents=[researcher, writer, editor],         # the team
    tasks=[research_task, write_task, edit_task], # the work
    process=Process.sequential,                  # execution strategy
    memory=True,                                # shared memory
    verbose=True,                               # log everything
    cache=True,                                 # cache tool results
)

# Trigger the crew
result = crew.kickoff(inputs={"topic": "agentic AI in 2026"})

print(result.raw)        # final string output
print(result.tasks_output)   # every task's output

💡 You don't write orchestration logic — you describe a team and the framework runs it.

Walk through each in detail:

1. Sequential — "Assembly line. Task 1, then Task 2, then Task 3. The output of each step feeds the next. This is what you should use 90 percent of the time. Predictable, debuggable, cheap."

2. Hierarchical — "There is a manager agent at the top who decides which worker handles which task at runtime. More flexible, but the manager can hallucinate sub-tasks or get into loops. Use only when the workflow truly cannot be predetermined."

3. Consensual (preview) — "Still being developed. Agents discuss and reach agreement before producing output. Like a meeting. Promising but not production-ready."

The pragmatic answer: "Start sequential. Move to hierarchical only when sequential cannot model your problem."

Tip: "Hierarchical mode often costs 3-5x more in tokens because the manager and workers all communicate." '>
10  /   PROCESS TYPES
Execution Strategies

Three Process Types

Process.sequential DEFAULT · USE 90% OF THE TIME
Tasks run in order. Output of each task is context for the next. Predictable, cheap, easy to debug. Think: assembly line.
Process.hierarchical FLEXIBLE · MORE EXPENSIVE
A manager agent receives the goal and dynamically delegates tasks to workers. Powerful for open-ended problems but harder to control. Costs 3-5x more in tokens.
Process.consensual PREVIEW
Agents discuss and converge on a shared answer (like a meeting). Still in development — not yet production-recommended.

13  /   MEMORY TYPES
Persistent Context

Four Types of Memory

By default, agents are stateless. Memory gives them context that persists across tasks and runs.

Short-Term Memory DEFAULT
Lives for the duration of one crew run. Shared between all agents in the same kickoff(). Great for "what did the researcher just find?"
Long-Term Memory
Persists across multiple crew runs. Stored in a vector database. Used for chat-style applications where context spans sessions.
Entity Memory
Tracks people, organizations, places, and things mentioned across runs. Enables relationship reasoning ("Tesla was discussed in 3 prior reports").
Contextual Memory RECOMMENDED
Combines all three above and serves the most relevant context to the current task automatically. Enabled when you set memory=True.

14  /   EXAMPLE
Complete Crew

A Complete Crew in 30 Lines

from crewai import Agent, Task, Crew, Process

# 1. Define agents
researcher = Agent(role="Researcher", goal="Find facts on {topic}", backstory="...")
writer     = Agent(role="Writer",     goal="Draft an engaging article", backstory="...")
editor     = Agent(role="Editor",     goal="Polish for clarity & flow", backstory="...")

# 2. Define tasks
research_task = Task(
    description="Research the latest on {topic}. Cite 5 sources.",
    expected_output="A bullet list of key findings with citations.",
    agent=researcher,
)
write_task = Task(
    description="Write a 600-word article based on the research.",
    expected_output="A polished article in Markdown.",
    agent=writer,
    context=[research_task],   # pass research output forward
)

# 3. Assemble the crew
crew = Crew(
    agents=[researcher, writer, editor],
    tasks=[research_task, write_task],
    process=Process.sequential,
)

# 4. Run it
result = crew.kickoff(inputs={"topic": "agentic AI in 2026"})

17  /   TRADEOFFS
Honest Take

Strengths and Limitations

✅ Strengths

  • Intuitive mental model — roles map to how humans think about teams
  • Fast prototyping — working crew in under 50 lines
  • Rich tool ecosystem — 100+ built-in tools, custom tools easy
  • Native MCP support — added 2025
  • Active community — 46K+ stars, frequent releases
  • Memory system — short / long / entity memory built in
  • Model-agnostic — OpenAI, Anthropic, Gemini, local LLMs

⚠️ Limitations

  • Less granular control than LangGraph state machines
  • Debugging is hard when 5+ agents loop on each other
  • Token cost grows quickly with verbose backstories
  • Non-determinism — same inputs, different paths
  • Hierarchical mode is risky — manager agents can hallucinate sub-tasks
  • Production observability still maturing

CrewAI Flows

When Crews Aren't Enough: Flows

Crews are autonomous reasoners. Flows add deterministic, event-driven control flow on top.

from crewai.flow.flow import Flow, listen, start

class ContentFlow(Flow):

    @start()
    def generate_topic(self):
        return trending_crew.kickoff()

    @listen(generate_topic)
    def write_article(self, topic):
        if topic.score < 0.7:
            return self.generate_topic()  # retry — deterministic loop
        return writer_crew.kickoff(inputs={"topic": topic})

    @listen(write_article)
    def publish(self, article):
        cms.publish(article)

💡 Crews = reasoning. Flows = orchestration. Combine when you need both autonomy AND reliable control flow.

22  /   PRACTICE
What Actually Works

Seven Rules for Real Crews

  • 1
    Start with 2 agents, not 5. Add more only when you can name a real specialization. Each extra agent multiplies token cost and debugging surface.
  • 2
    Write specific backstories. "You are a writer" is weak. "You are a science journalist who explains complex topics with vivid analogies" steers the model meaningfully.
  • 3
    Define expected_output precisely. CrewAI uses it to validate completion. Vague expected outputs cause infinite loops.
  • 4
    Use sequential before hierarchical. Manager agents are powerful but unpredictable. Pin down the workflow before delegating control.
  • 5
    Cap iterations. Set max_iter on agents. Without it, an agent can loop on tool calls until your wallet cries.
  • 6
    Log everything in dev. Use verbose=True. Pipe to a tracer like Langfuse or Helicone in prod.
  • 7
    Test with cheap models first. Iterate prompts on gpt-4o-mini, then scale to gpt-4o for production.

25  /   SUMMARY
Remember This

Five Things to Remember

  • 1
    CrewAI is role-based. Agents are defined by who they are — Researcher, Writer, Editor — not by code paths.
  • 2
    Six concepts cover 95% of usage: Agent, Task, Crew, Tool, Process, Memory.
  • 3
    Sequential first, hierarchical when needed. Predictability beats flexibility for most workflows.
  • 4
    The tradeoff: easiest multi-agent framework, but less granular control than LangGraph.
  • 5
    Best for: rapid prototyping, content generation, research workflows, and any task where roles cooperate.
